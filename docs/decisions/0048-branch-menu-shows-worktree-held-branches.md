# 0048 — 会话框分支菜单如实显示被工作树占用的本地分支

状态：已接受

## 背景

会话框（`conversation.input.left`）的分支芯片菜单有两处独立的过滤叠加在一起：

1. `buildBranchRows`（`src/client/BranchChip.tsx`）把已被某个 linked worktree 检出的本地分支从「本地分支」组里剔除，只在「工作树」组留一行跳转入口。
2. 主仓库的会话一旦开始（非 blank），整个「工作树」组不渲染（`canAdopt = session.blank || inLinkedWorktree`）。

两者同时成立时，菜单里就只剩没被工作树占用的分支。实际反馈：`tauri-navicat` 有 `main`、`perf/query-streaming`、`perf/stream-preview-eval-20261115` 三个本地分支，后两个各有独立 worktree 且会话正在运行，于是弹出菜单只有 `main`——用户以为分支丢了，右侧 Git 面板却仍显示 3 个。

原设计和注释的理由是「git 拒绝重复检出，本地行会是死路」。但**隐藏**等于让用户失去对仓库分支的完整视图，这个代价高于一行点击后失败的提示。

## 决策

- `buildBranchRows` 不再剔除被工作树占用的本地分支：全部本地分支都进「本地分支」组，ahead/behind 照旧带上。
- 「工作树」组保持不变：仍为每个 linked worktree 提供一行跳转入口（该行与本地行同名但语义不同——本地行是在本目录检出，工作树行是跳到已有会话）。
- 不做额外处理：不标记「已在其他工作树检出」，不禁用、不拦截点击，也不改 `git` 行为。同一分支在本目录检出会被 git 自己拒绝并如实报错，如何使用分支由用户决定，插件只如实呈现与执行。

被否决的备选：① 加「已在其他工作树检出」标注并禁用行——把产品判断强加给用户，超出 Git 管理本身；② 保留剔除但让「工作树」组在已开始的主会话也显示——那会恢复回两套分组语义的纠缠，且仍不解决本地分支缺失的观感。

## 影响

- 正面：会话框菜单的分支列表与 `git branch` / Git 面板一致，不再有「分支消失」的错觉。
- 代价：主仓库的空白会话里，同一分支会同时出现在「本地分支」与「工作树」两组（前者检出、后者跳转）；分组标题与行为差异可区分，接受这一重复。
- 回归：`tests/branch-tree.spec.ts` 的 `buildBranchRows` 用例改为断言被占用分支留在本地组且仍保留工作树行。
