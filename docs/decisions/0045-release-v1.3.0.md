# 0045 — 发布 v1.3.0 次版本

状态：已接受

日期：2026-11-04

## 背景

自 v1.2.0 后，仓库新增完整的 Git 网络可靠性能力：加速 URL 修正（0040）、网络操作预算/推送核验（0041）、直连失败时的 IP 优选（0042）、显式代理与诊断（0043），以及镜像失败回直连和 SSH 提示（0044）。用户发起将版本升级到 v1.3.0，并要求提交 GitHub、通过 CI、创建 tag 与 GitHub Release、触发 npm 构建/发布，且 npm 包内版本日志明确说明升级内容。

## 决策

将 `package.json` 的 `version` 从 `1.2.0` 升到 `1.3.0`，作为独立 chore 提交，并在同一提交更新此记录与 `CHANGELOG.md`。日志以用户可感知的网络能力变化为主，说明网络备用通道、代理与诊断、推送前探测/超时核验、镜像失败回退及 SSH 提示。`CHANGELOG.md` 已包含在 npm 包的 `files` 中。

验证通过后将提交推送到 `main`。release 工作流由 `v1.3.0` tag 触发，会校验 tag 与 package.json 版本一致，依次运行类型检查、测试、构建并发布 npm 包，再创建/更新 GitHub Release 并附 tarball。CI 工作流对 main push 执行验证。

被否决的备选：

- 将版本升号并入网络功能提交——被否决：发版升号必须独立为 chore 提交。
- 发布补丁版本 `1.2.1`——被否决：本次发布包含一组完整的新网络功能，采用次版本号 `1.3.0`。
- 手工绕过 tag 工作流上传 npm——被否决：仓库既有自动化明确以匹配的 `vX.Y.Z` tag 作为发布入口，便于 CI 校验并保证 npm 与 GitHub Release 一致。

## 影响

- 正面：npm 用户可通过包内 `CHANGELOG.md` 了解 v1.3.0 的网络能力；成功的 `v1.3.0` tag 触发 CI/CD，发布 npm 与 GitHub Release。
- 负面：发布依赖 GitHub Actions secret `NPM_TOKEN` 有效，CI 或 release 检查失败时不得将其视为已发布。
- 升号本身不改变运行时行为；新增网络通道的具体影响见决策 0040–0044。
