# 0014 — 面板卡片高度受控与分支树折叠/定位

状态: 已接受

日期: 2026-10-24

## 背景

Git 管理面板（0013）三张卡片自然高度纵向堆叠，外层整体滚动。分支树挂载时本地与远程两组全展开：分支一多（远程树动辄上百行），分支卡片把未提交变更与提交历史挤出屏幕；提交历史一页 50 条同样占满整屏。用户要求：各卡片限高；分支卡片提供「全部展开 / 全部收起」；打开面板默认定位到当前分支。

## 决策

- **卡片限高（内部滚动替代整体滚动）**：分支树与提交历史的 body 各加 `max-height: 40vh` + `overflow-y: auto`（`overscroll-behavior: contain` 防滚动链外溢）；未提交卡片的文件列表单独包一层 `max-height: 30vh` 的滚动区，**提交框留在滚动区外**——500 行变更树不允许把提交入口顶出视野。外层整列滚动保留，只在各上限之和超出面板高度时介入。被否决：三卡片按弹性比例瓜分面板高度（flex 拉伸）——面板里还有顶栏与不同卡片的天然高度差，比例分配在内容少的仓库会出现大片留白，且实现复杂；vh 上限实现简单、短内容时卡片自然收缩。
- **分支树默认折叠远程**：挂载态为 `COLLAPSED_ON_MOUNT = {'remote'}`——本地组展开（`buildBranchRows` 已把当前分支排在本地首位，展开即见），远程组整树折叠。「灾难场景」由远程树贡献，默认折叠即消除；用户用组头自行展开单个 remote。
- **全部展开 / 全部折叠**：分支卡片头部两个文字按钮（复用既有 `menuExpandAll` / `menuCollapseAll` 文案键，与 chip 菜单用词一致，不新增词典项）。展开=空折叠集；折叠=`branchGroupKeys(remotes)` 全键集（`local`、`remote`、`remote:<name>`），该纯函数落在 `git-panel-data.ts` 并有规格覆盖。
- **默认定位当前分支**：当前分支行标记 `data-current`；`useLayoutEffect`（无依赖数组，检出与展开后各状态路径都能触达）在两种情形把当前行垂直居中于卡片滚动区——检出发生分支变化（对比 `locatedRef` 记录的上次定位名），或「全部展开」置位 `pendingLocateRef`。同名刷新（暂存、提交后的 `loadAll`）不打扰用户滚动位置；行未渲染（其组被手动折叠）时不动作。居中用 getBoundingClientRect 差值而非 offsetTop（行与滚动容器间无定位祖先保证）。被否决：`scrollIntoView`——会连带滚动所有可滚动祖先（外层整列、宿主页面），把整面板一起拽走。

## 影响

- 正面：分支密集的仓库不再把其余卡片挤出首屏；三卡片各自内部滚动，长内容互不挤压；打开面板即可见当前分支，检出与全部展开后自动回到当前分支。
- 正面：提交框在变更树超限时保持可见；`branchGroupKeys` 成为纯函数并有测试，折叠全键集的口径被规格锁定。
- 负面：三处独立滚动区引入嵌套滚动——外层整列仍有滚动条，用户需在卡片内/整列间切换滚轮目标（`overscroll-behavior: contain` 缓解越界链式滚动）；vh 以视口为基准，宿主侧栏高度显著小于视口时上限偏松。
- 负面：远程组默认折叠改变既有行为——习惯默认看远程树的用户每次多一次点击（「全部展开」一键可达）。
- 兼容性：纯客户端展示层变更，不涉路由、wire 协议与设置；包版本保持不变。
