# 0002 — 发布 v1.0.1 补丁版本

## 背景

v1.0.0 发布后又合入了若干修正与说明类提交（如修改说明、调整名称），内容不足以构成次要版本，但相对已发布的 1.0.0 有实际差异，需要发布一个补丁版本让用户拿到最新代码。同时本仓库 AGENTS.md 要求发版升号必须由用户发起，且作独立的 chore 提交。

## 决策

将 `package.json` 的 `version` 从 `1.0.0` 升到 `1.0.1`，作为独立的 chore 提交提交，并打 tag `v1.0.1` 推送到 GitHub，通过 tag 触发 release 发布。备选方案：把变更归入下一个次要版本（1.1.0）——被否决，因为本次变更以修正说明为主，不引入新功能，按语义化版本应使用补丁号。

## 影响

- 正面：npm 与 GitHub releases 上的版本与仓库实际状态一致，用户可升级到最新修正。
- 负面：多占用一个版本号；后续若在发布前又发现 1.0.1 的缺陷，需要再升 1.0.2。
