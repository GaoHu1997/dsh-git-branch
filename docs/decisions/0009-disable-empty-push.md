# 0009 — 禁用无可推送提交的推送按钮

日期: 2026-10-01
状态: 已接受

## 背景

分支菜单此前只按菜单和网络操作状态禁用推送。当前分支已经与上游同步、没有上游，或状态尚未加载时，用户仍可点击推送，最终只能得到无效操作或 Git 的拒绝信息。

## 决策

- 推送按钮仅在当前分支行存在 `ahead > 0` 时启用。
- `ahead` 缺失（没有 upstream、分支不可比较、状态未加载）或为 `0` 时，按钮使用原生 disabled 状态，并显示对应的不可用原因。
- 插件继续执行裸 `git push`，不自动选择 upstream，也不传 `--force`。
- 将现有 `icon.svg` 声明为 package 的 `icon`，并加入 npm `files`，保证宿主读取的图标随发布包提供。

## 理由

推送动作的目标是当前分支已存在的本地提交；`ahead` 是 Git 已计算出的唯一可靠信号。没有 upstream 时插件无法安全推断目标，没有 ahead 提交时点击也不会产生有效变化。由 manifest 声明并发布同一份 SVG，可避免图标只存在于源码仓库而在安装包中缺失。

## 验证

新增分支状态谓词测试和 package 图标元数据测试；完整测试、host 构建和 client 类型检查继续作为交付验证。

## 影响

- 正面：没有可推送提交时按钮不可点，用户不会再拿到无效操作或 Git 的拒绝提示，界面同时给出不可用原因。
- 正面：`icon.svg` 随包发布，安装包的插件卡片图标不再缺失（此前只在源码仓库里）。
- 负面：`ahead` 依赖分支状态，状态尚未加载的一瞬间按钮是禁用的，需要等状态返回。
