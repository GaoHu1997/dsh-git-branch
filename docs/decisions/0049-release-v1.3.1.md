# 0049 — 发布 v1.3.1 补丁版本

状态：已接受

日期：2026-11-15

## 背景

v1.3.0 之后唯一的用户可见问题是会话框分支菜单的显示缺口（决策 0048）：已被 linked worktree 检出的本地分支在菜单中不可见，用户会误以为分支丢失。修复是前端展示层的单点改动（`buildBranchRows` 去掉剔除逻辑），不涉及接口、协议或运行时行为变化。用户发起将版本号 +1、提交 GitHub 并创建 tag 与 Release。

## 决策

将 `package.json` 的 `version` 从 `1.3.0` 升到 `1.3.1`，作为独立 chore 提交，并同一提交更新本记录、`CHANGELOG.md` 与 `.github/releases/v1.3.1.md`。修复本身单独提交（含决策 0048 与回归用例），与升号分离。

被否决的备选：

- 升次版本 `1.4.0`——被否决：无新增能力，只是展示修复，按语义化版本取补丁号。
- 与修复合并为一个提交——被否决：AGENTS.md 要求版本号变更是独立 chore 提交。

## 影响

- 正面：`v1.3.1` tag 触发 release 工作流，校验 tag 与 `package.json` 版本一致后走类型检查、测试、构建、发布 npm，并用 `.github/releases/v1.3.1.md` 作为 GitHub Release 正文。
- 负面：发布仍依赖仓库 secret（`NPM_TOKEN`）有效；工作流失败即视为未发布，需修复后重推 tag。
- 运行时行为无变化，仅分支菜单的内容更完整。
