# 0015 — 分支菜单改右键、跨面板刷新、/switch 切会话自己的检出

状态: 已接受

日期: 2026-10-24

## 背景

用户反馈三个问题：① 分支卡片里左键点击才弹操作菜单，按 IDEA 习惯应为右键；② 在面板里切换分支后，会话输入框上的分支 chip 不更新；③ 怀疑切换是假的——分支没真正切到当前项目。

第③条经查属实：`/switch` 用 `probeRepo().repoRoot` 作为执行目录，而 `repoRoot` 是**主检出**（`dirname(git-common-dir)`，0013 为 `worktree remove` 之类的仓库级操作特意这么定义）。因此在 linked worktree 里开的会话点检出，动的是主检出、会话自己的 worktree 纹丝不动——面板随后重新读 `/status` 仍显示旧分支，看起来就像"没切成"。主检出会话不受影响。

第②条的根因是两套独立快照：chip 与面板各自持有 `/status`，互不知情。chip 只在挂载、窗口重新聚焦、以及自己操作后刷新；面板检出时窗口一直聚焦，chip 永远不会重新拉取。

## 决策

- **分支行改右键弹出菜单**：`onClick` → `onContextMenu`（`preventDefault` 抑制浏览器原生菜单，按行矩形定位浮层）。键盘可达性保持——行仍 `role="button" tabIndex=0`，Enter/Space 等效打开菜单（上下文菜单没有键盘孪生，若一并砍掉键盘入口就成了纯鼠标功能）。行光标从 `pointer` 改回 `default`：左键已无点击语义，指针手型会误导。被否决：左右键都弹菜单——左键点击在 IDEA 里是选中行，弹菜单会让选中动作变得不可做。
- **`/switch` 改在会话目录自身的 toplevel 执行**：`handleSwitch` 传 `facts.toplevel` 而非 `facts.repoRoot`；`switchBranch` 的参数语义随之从"主工作树目录"改为"要移动的检出目录"（`worktree prune` 仍是仓库级、在该目录跑同样有效）。warning：git 本身会拒绝检出被其他 worktree 占用的分支——在 worktree 会话里点「检出 main」现在得到一条诚实的 git 报错，而不是"成功"地移动了主检出。**这是有意的行为变化**：宁可报错也不动用户没在看的检出。被否决：保留 repoRoot 但切换后强制刷新面板——只治"看起来没变"，分支仍切在错误的目录；被否决：worktree 会话里禁用检出——无用动作做成灰按钮不如让它报错说明原因。
- **跨面板变更通知**：新增 `src/client/git-events.ts`（模块级监听器集合，`emitGitMutated` / `onGitMutated`）。面板每个变更动词成功后 emit，chip 与面板都订阅；chip 自己在 `runGuarded` 成功路径 emit（双向）。两边都复用已有的 `busy` 互斥与请求序号守卫，因此自触发的那次回声只是一次幂等的多余 `/status`，不会落地旧快照。被否决：宿主侧 `fs.watch(.git/refs)` + SSE 推送——为两个组件之间的一次本地通知引入服务端通道，复杂度不成比例（0013 里同一个判断已做过一次）；被否决：把分支状态提升到共享 store——宿主 store 契约需要镜像，收益只是省一次 fetch。

## 影响

- 正面：面板与 chip 的分支显示在任一侧操作后立即一致；worktree 会话的检出终于作用于它自己（此前是一个不可见的错误行为）；分支行的交互符合 IDEA 语境菜单习惯。
- 正面：`/switch` 的语义与 `/branch`「在查询目录的检出上操作」对齐，不再是同族路由里的两个例外。
- 负面：worktree 会话里想切到其他 worktree 正在使用的分支会收到 git 报错，必须先释放对方——这是 git 的限制，现在如实暴露。
- 负面：每次变更多一次 `/status` 请求（chip）与一次三段重读（面板）。本地 git 调用，实测可忽略；若将来变更频率显著上升，可给发信加节流。
- 负面：`git-events` 是客户端模块级单例，依赖宿主把 chip 与面板加载进同一个 bundle 实例。本插件的两个入口都由同一 `client.js` 提供，满足前提；打包方式若改为多 bundle，需要换成宿主提供的总线。
- 兼容性：路由出参、wire 契约、设置项均未变；包版本保持不变。
