# 0017 — 发布 v1.0.4 补丁版本

状态: 已接受

日期: 2026-10-25

## 背景

自 v1.0.3 以来，Git 管理面板累计了 10 个提交：面板卡片高度比例定稿为 2:1:2、提交框常驻卡片底部、分支树默认折叠远程并支持全部展开/收起与定位当前分支、当前分支行整行高亮、提交历史圆点与作者徽标调整、分支菜单改为右键菜单、面板与 chip 分支状态双向同步、`/switch` 改切会话自身检出、分支卡片标题栏新增分支搜索框（0014–0016）。已发布的 1.0.3 不含这些改进，用户需要新版本获取。用户明确指示「版本 +1」并要求提交、推送、tag 与 release。按 AGENTS.md 约定，升号作为独立 chore 提交。

## 决策

将 `package.json` 的 `version` 从 `1.0.3` 升到 `1.0.4`，作为独立 chore 提交（与该提交一起带上本决策记录），打附注 tag `v1.0.4` 推送，由 release 工作流（0010）校验 tag 与版本一致后发布 npm 并创建 GitHub Release。

被否决的备选：

- 升到次要版本 1.1.0——用户明确说「版本 +1」，且本仓库历次发布（1.0.1–1.0.3）一律按补丁号递增，延续该惯例避免版本号跳变。
- 把版本号改动并进功能提交——被否决：AGENTS.md 要求发版升号作独立 chore 提交，tag 需要一个干净的锚点。

## 影响

- 正面：npm 与 GitHub Releases 的最新版本包含面板卡片布局、右键分支菜单、状态双向同步、分支搜索框等全部改进。
- 正面：tag 与 `package.json` 版本由工作流强校验，误发会在构建前失败。
- 负面：多占用一个版本号；发布前若再发现缺陷需再升 1.0.5。
- 依赖：发布依赖仓库 secret `NPM_TOKEN`（见 0010），凭据失效会导致发布步骤失败但不产生半成品 Release。
