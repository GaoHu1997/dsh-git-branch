# 0019 — 提交历史图、筛选与右键操作

状态：已接受  
日期：2026-10-27

## 背景

提交历史需要展示所有分支及合并关系，并提供提交人、分支、时间筛选，以及在历史提交上创建分支和标签的右键操作。

初次实现的图线在行间断开：SVG 固定高 44px，而提交行上下各有 6px padding，父列表另有 8px gap，造成约 20px 的几何缺口。展开文件列表还会增加缺口。纯 lane 数据测试无法覆盖这种 DOM 布局问题。

## 决策

- 历史请求默认使用 `--all --topo-order`，按 parent 计算多车道与合并边；筛选在服务端作用于分页查询，标题栏顺序为提交人、分支、时间。
- 提交条目的右键菜单支持复制、基于提交创建本地分支和创建本地标签；写操作复用现有路由校验。
- 行列表单独包成不收缩的 block，消除提交行之间的 gap；垂直 padding 移至文字列，让图形区域直接接触行的上下边界。保留共享 sectionBody 的间距，避免影响其他卡片。
- 所有行使用全图统一宽度，SVG 通过 `preserveAspectRatio="none"` 撑满实际标题行高，路径使用 `vector-effect="non-scaling-stroke"` 保持线宽。节点作为固定 8px 的独立元素定位，避免圆点随 SVG 缩放变形；不引入 ResizeObserver 状态，因为当前两段布局能直接随 CSS 高度变化。
- 文件展开区域单独延续所有 `through` 和 `out` 目标车道，`in` 已在节点终止，不能延长。展开区的 SVG 高度随实际文件数和加载状态变化。
- 回归检查使用真实 Chromium 浏览器，将 SVG 路径端点经 `getScreenCTM()` 映射至屏幕坐标，检查相邻行及展开区域共享端点差不超过 0.5 CSS px，同时检查节点尺寸。覆盖线性、三父合并、独立分支、展开加载/失败/空/多文件、窄宽、高文字行高、125% 缩放和追加分页。

## 影响

- 提交行和展开文件区域在任意实际高度下都能保持线条连续，不再依赖 SVG 固定高度恰好等于内容高度。
- 节点保持 8px 圆形，线宽稳定，横向车道间距保持 14px；曲线随标题行高纵向变化。
- 图形几何测试需要真实浏览器：Windows 默认使用已安装的 Edge；其他环境通过 `PLAYWRIGHT_CHROMIUM` 指定可执行文件，没有浏览器时跳过该组测试。现有数据层测试继续覆盖 Git 参数和 lane 计算。
- 全分支历史仍按页加载，车道可能增加图列宽度；展开内容使历史卡片内部滚动。
