# 0005 — 放宽 DSH peer 依赖版本为范围适配

日期: 2026-06-10
状态: 已接受

## 背景

插件的 peerDependencies 此前将 `@deepseek-ai/dsh-host-webserver` 与 `@deepseek-ai/dsh-settings` 固定写为 `^0.1.7-rc.1 || ^0.2.0-rc.1`。DSH 升级到 `0.2.0-rc.2` 后插件无法使用,每次 DSH 发新 rc 都要同步改插件版本。

## 决策

改用显式 semver 范围,覆盖 `0.1.7-rc.1` 起到 `0.3.0`(不含)的所有版本,包括正式版与预发布版:

```
>=0.1.7-rc.1 <0.3.0-0 || >=0.2.0-0 <0.3.0-0
```

同时应用于 `@deepseek-ai/dsh-host-webserver` 和 `@deepseek-ai/dsh-settings`(`package.json:78-79`)。

## 理由

- npm semver 规定:预发布版本只能被带同元组预发布标签的比较器匹配,普通范围如 `^0.2.0-rc.1` **不会**匹配 `0.2.0-rc.2`。
- 写法 `>=0.1.7-rc.1 <0.3.0-0` 中,上限用 `-0`(即 `0.3.0-0`,semver 中最低的预发布级别)使 `0.3.0-rc.x` 与 `0.3.0` 均被排除,而 `0.1.x`/`0.2.x` 的所有 rc 与正式版均命中。
- 第二个分支 `>=0.2.0-0 <0.3.0-0` 冗余但无害;保留是为了语义清晰(明确声明 0.2.x 整段支持)。

## 验证

semver 7.8.5 实测:`0.1.7-rc.1`、`0.1.7`、`0.1.9`、`0.2.0-rc.1`、`0.2.0-rc.2`、`0.2.5` → 满足;`0.3.0-rc.1`、`0.3.0` → 不满足。

## 影响

- DSH 后续 `0.2.x` 系列升级(含 rc)无需再改插件 peer 范围。
- 若 DSH 出现 `0.3.0`,仍需手动评估并扩大上限,但至少不再逐个 rc 修。
