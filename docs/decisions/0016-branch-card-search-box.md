# 0016 — 分支卡片标题栏加分支搜索框、去掉标题栏分支数量

状态: 已接受

日期: 2026-10-24

## 背景

Git 管理面板（0013/0014/0015）的分支卡片把本地/远程分支整树铺开，分支多的仓库里找一个分支只能靠折叠树组与滚动。用户要求：① 分支卡片加搜索框，按分支名称过滤；② 搜索框可以放进标题栏；③ 标题栏上的分支数量移除。

## 决策

- **搜索框放标题栏**：位于标题「分支」右侧、工具组（全部展开/全部折叠/新建分支）左侧，复用提交历史卡片已有的 `searchBox`/`searchInput` 样式，新增 `searchBoxHead` 变体（`src/client/GitHistoryPanel.module.css`）改掉 `margin-left: auto` 与宽度约束，让输入框在标题与工具之间生长。被否决：放卡片正文顶部——与用户指定的标题栏不符，还白吃一行正文高度；被否决：把工具组挪下标题栏腾位置——用户只让移除数量徽标，工具按钮不动。
- **文案复用既有词条**：占位符与空态用 `menuSearchPlaceholder`（搜索分支）与 `menuNoMatches`（没有匹配的分支），不新增 `panel.*` 词条。分支卡片本来就在复用 `menu.*` 文案（`menuExpandAll`/`menuNoBranches` 等），跟随既有做法；为两条已有文案再造 `panel.*` 同义键只会让词典膨胀。
- **过滤规则**：纯函数 `filterBranches(rows, query)`（`src/client/git-panel-data.ts`）——trim 后大小写不敏感的分支名子串匹配，空查询返回全部（与同文件 `filterCommits` 同族），配单测（`tests/git-panel-data.spec.ts`）。远程行按全名 `remote/name` 匹配：全名天然包含树上显示的去前缀短名，因此「搜用户看到的名字」与「搜 origin 前缀」都能命中。被否决：仅匹配去前缀短名——搜 `origin` 会一无所获，把远程归属这一可见信息排除在搜索外没有理由。
- **搜索期行为**：查询非空时忽略折叠状态、直接展开所有命中分组（藏起来的命中等于没搜到），且不动用户手设的折叠集合——清空搜索即恢复原状；分组头计数跟随过滤结果（0014 保留的本地/远程/各远程分组计数在搜索中显示命中数，不显示会说谎的全量数）。被否决：搜索时自动折叠未命中分组但保留命中分组的折叠状态——同一棵树上两种折叠来源（用户手点 vs 搜索）混在一份状态里，行为难解释。
- **标题栏分支数量徽标移除**（用户明确要求）：`sectionHead` 里的 `countBadge`（本地+远程总数）删除；分组头计数保留。卡片空态判定仍用总数（无分支 → 「暂无分支」，搜索无命中 → 「没有匹配的分支」）。

## 影响

- 正面：分支多的仓库里定位分支从「滚动+折叠」变成一次输入；搜索框就在卡片头部，不占正文高度。
- 正面：过滤逻辑是纯函数并有单测，与 `filterCommits` 同族同规矩。
- 负面：标题栏一行同时容纳标题、搜索框、三个工具按钮，窄侧栏下搜索框会被压缩到 `min-width: 90px`；若日后工具按钮继续增多，需要把搜索框挪到第二行（本次按用户指定放标题栏）。
- 负面：当前分支行被过滤掉时卡片不再居中定位（定位目标未渲染，属预期）；清空搜索后若当前分支行仍不在折叠组内则不重新定位（与既有 locate 规则一致）。
- 兼容性：纯客户端展示层变更——路由、wire 契约、设置项、locale 词条均未变；包版本保持不变。
